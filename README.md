SwarmOps is a enterprise-grade **AI-powered Infrastructure Assistant and Incident Operations Platform** designed for SREs, DevOps engineers, and IT Infrastructure teams. 

---

## 🚀 Problem Statement & Solution

### The Problem
In modern IT environments, infrastructure teams handle hundreds of incident tickets daily—ranging from network degradation and database deadlocks to microservice timeout cascades. When new outages occur, engineers manually search through fragmented logs, historical tickets, and root-cause analysis (RCA) documents to find matching historical incidents. This manual search increases **Mean Time to Resolution (MTTR)** and leads to repetitive troubleshooting.

### The SwarmOps Solution
SwarmOps solves this by providing a unified **Hybrid AI Search Platform**:
1. **Natural Language to SQL**: Query incident metrics, assignment groups, and criticalities in plain English (e.g., *"How many open critical incidents are assigned to Database Team?"*).
2. **Semantic Vector Search (RAG)**: Search historical incidents by problem description or error logs using 768-dimensional `pgvector` embeddings generated by `nomic-embed-text`.
3. **On-Premise Privacy**: Uses local open-source LLMs (`gemma3:4b-it-q4_K_M`) via Ollama—ensuring zero data leakage to external APIs.
4. **Single-Page Operational Dashboard**: Real-time KPI cards (`Open`, `In Progress`, `Pending`, `Closed`), scrollable incident list popups, clickable Incident ID anchor links, and an integrated AI assistant.

---

## ✨ Key Capabilities & Features

- **Single-Page Operations Dashboard**: Compact, fit-to-screen SwarmOps workspace with dynamic incident count cards and interactive state popups.
- **Intelligent Query Classifier (`Manager`)**: Automatically routes queries to:
  - `SQL`: Natural language SQL generation for metrics, counts, and filtered table queries.
  - `VECTOR`: Semantic similarity search across incident descriptions and resolution notes.
  - `FOLLOW_UP`: Rewrites multi-turn context (resolving pronouns like *"it"*, *"this incident"* to exact IDs like `INC20260465`).
  - `GENERAL`: Answers general DevOps/Infrastructure questions without hallucinating data.
  - `INVALID`: Blocks destructive SQL commands (`DELETE`, `DROP`, `UPDATE`).
- **User Session & History Persistence**: Restores previous chat conversations per user session and supports instant history clearing.
- **Automated Data Ingestion Pipeline**: Built-in script (`load_data.py`) imports 500+ incident JSON records into PostgreSQL and batch-generates vector embeddings via Ollama.
- **Persistent Docker Microservices**: Configured with dedicated volumes (`ollama_data` and `incident_db_data`) so LLM models and database records persist seamlessly across `docker compose up` / `down`.

| Container Name | Service | Tech Stack | Internal/Published Port | Description |

| `inc_ollama` | AI Engine | Ollama | `11434:11434` | Hosts `gemma3:4b-it-q4_K_M` & `nomic-embed-text` |

## 🛠️ Quick Start Guide (Commands to Run)

### 1. Clone the Repository
```bash
git clone https://github.com/Aravind8967/Infrastructure-AI-Assistant.git
cd Infrastructure-AI-Assistant
```

### 2. Start the Complete Stack
Run Docker Compose to build and start all 4 microservice containers:
```bash
docker compose up -d
```

> **Note**: On first startup, `inc_ollama` will automatically verify and download the `gemma3:4b-it-q4_K_M` LLM and `nomic-embed-text:latest` embedding models if they are not already present in the `ollama_data` volume.

### 3. Access the Application & APIs
- 🌐 **SwarmOps Web Dashboard**: [http://localhost](http://localhost)
- 📚 **FastAPI Interactive Docs (Swagger)**: [http://localhost:8000/docs](http://localhost:8000/docs)
- 🦙 **Ollama API**: [http://localhost:11434](http://localhost:11434)
- 🐘 **PostgreSQL Database**: `localhost:5432` (`user: postgres`, `password: postgres123`, `db: incident_db`)

## 📥 Ingesting Sample Data & Vector Embeddings

If you want to populate or reload the database with 500 sample infrastructure incidents and generate their vector embeddings:

```bash
docker exec -it inc_backend python load_data.py
```

This utility will:
1. Parse `incident_management_500.json`.
2. Insert 500 incidents into `incident.incidents` in PostgreSQL.
3. Call Ollama (`nomic-embed-text`) to generate 768-dimensional embeddings for semantic search.

## 🗄️ Database Architecture

The PostgreSQL database (`incident_db`) is organized into three clean schemas:

- `identity`: User accounts and roles (`identity.users`).
- `conversation`: Chat transaction history (`conversation.messages`).
- `incident`: Infrastructure incident records (`incident.incidents`), indexed by `category`, `service`, `state`, `criticality`, `assignment_group`, and `embedding` (using `pgvector`).
